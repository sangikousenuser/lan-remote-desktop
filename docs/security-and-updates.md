# LAN Remote Desktop v0.9 — セキュリティ・権限・署名付き更新

## 信頼境界

1. LANケーブル接続だけでは信頼しない。mDNSの発見応答も未認証として扱う。
2. 初回のみWindowsの操作対象ユーザーとMacの両側でペアリング承認。短い確認コードは認証済み鍵交換に結び付け、番号の一致を確認。端末公開鍵fingerprintとWindowsユーザーセッションを登録。
3. 二回目以降は既知公開鍵のHostを優先表示しMacの接続確認を必須とする。承認がない状態では画面、音声、キーボード、クリップボード、ファイルのアクセスを開始しない。
4. 同一Windows PC全体で操作可能なMacは1台。ユーザーセッションを跨ぐ接続競合も管理された共有排他ロックで制限する。二重接続なら`SESSION_BUSY`。
5. AES-GCM/ChaCha20-Poly1305などの認証済み暗号化を認証済みTransportに適用。QUICの場合TLS1.3が暗号化を担当。TLS＋UDPの場合UDPの認証・replay対策を別途実装。暗号を自作しない。
6. 操作権限、クリップボード権限、転送権限をセッション状態で分離し、突然の切断時にすべて無効化。
7. 個人利用でもMac 10.13はOSセキュリティ更新が期待できない。LANのHostポートをインターネットへ公開しない。ファイアウォールを無効にしない。

## Windows各ユーザー個別Host

Per-machine Installは実行ファイルをPC全体で共有するだけであり、各ログイン時のユーザーセッションで**別Hostプロセス**を起動する。Pairing DB /秘密鍵/設定/ログはユーザー単位に保存し、他ユーザーへの権限横断を拒否。Session 0サービスで直接キャプチャを行わない。UAC/ロック画面は初期対象外。

## 管理者権限が必要なネットワーク変更

- Ethernetアダプターはユーザーが選択。MACアドレス/OS interface identifierで固定し、単なる"Ethernet"という表示名だけに依存しない。
- 初回に管理者承認を求め、許可されたNICに対する`ReadSettings`/`ApplyStaticAddress`/`RestoreSnapshot`のみを実行する狭い権限のHelperを用意する。任意コマンド実行・任意パス操作は禁止。
- Helperは呼び出し元のコード署名/プロセスID/認可情報を確認する設計とする。署名なし配布で実現できる安全なOS公式の権限委譲経路をPhase0で検証し、不可なら毎回OS管理者承認を再要求する。**初回承認後の無条件永続root実行を行わない。**
- IPの既存設定・DHCP・IPv6・DNS・ゲートウェイ・ルート・ユーザー変更検出用の世代を記録。アプリ管理下のNICだけ更新。DNSやWi-Fiの設定は書き換えない。直結用NICにはデフォルトGWを足さない。
- 「ケーブル取り外しで復元」を正常系とし、クラッシュやイベント取り逃しに備えてHelper側タイムアウト/起動時照合も作る。120秒セッション再接続とIP復元の基準は独立（Q49）。
- DHCP/Link-Localが正常なら固定IPを作らない。衝突を検査し、両端に事前操作が必要な場合をUIで案内。相手端末のIPを通信不能状態から遠隔設定できるとは仮定しない。

## 自動更新の要求仕様

- Stableのみ取得。Windows/MacがそれぞれGitHub ReleasesへHTTPSアクセスし、オフライン時は更新を保留。画面転送と更新ネットワークは分離。
- 更新確認 → 署名付きRelease Manifest → 対応OS/CPU/アプリバージョン/プロトコル確認 → 本体DL → ハッシュ検証 → **必ず独立鍵で署名検証** → `STAGED`永続化。
- 更新はセッション中に勝手に適用しない。`STAGED`は次回起動時に更新Helperが適用。必要ならHost/Client間で旧新バージョン互換性を交渉する。
- macOS 10.13はSparkle **2.9.6**を候補としてバンドル。要求どおり「次回起動時適用」が実現できるかPoCで確認し、不可能なら補助プロセスで安全な起動前更新。SparkleのEdDSA公開鍵はビルド済アプリへ埋め込む。
- Windows Per-user更新はそのユーザー領域のみ、Per-machine更新は管理者/認証済みUpdaterを経由。低権限プロセスにProgram Filesへの書込みを許可しない。
- **ロールバック**: 旧版実行ファイルと設定スナップショット、トランザクション状態、起動成功の観測期限を保持。新版が起動できない、ハートビート出さない、署名/整合性不適合なら旧版へ戻す。数度連続失敗した更新版はブロックリスト入り。ユーザーデータ・鍵・転送データをロールバック中に削除しない。
- 署名なしmacOS `.app`を使う場合、初回Gatekeeperで明示操作が必要となることがある。Gatekeeper全体無効化は推奨しない。Sparkle署名はDeveloper IDと別。

## Github公開Releaseと署名の完全性

- Public RepoでPush/PRのコードをテスト。PRにrelease secretsを渡さない。
- `vX.Y.Z`タグ作成 → CI build → SHA256保存 → High Sierra実機手動チェック → `release` GitHub Environmentでreviewer承認 → Release署名・公開。
- Environment Secretの署名秘密鍵は`release` Jobだけへ提供。`contents: write`は公開Jobだけ。Github Actionsの署名/公開JobはPRの非信頼コードを直接実行しない。
- **承認だけでビルド・更新コードの信頼性は保証されない**：変更したワークフローと署名対象artifactの供給元コミットを確認し、release tagを保護、ジョブ権限を最小化する。
- `release.yml`は[候補のbytes・実装完了・実機受入の照合](releasing.md)後だけEnvironment承認と署名・draft検査・公開へ進む。現在は実装完了ゲートfalse、署名secret未登録であり正式公開を行わない。
- 秘密鍵ローテーションは署名鍵変更を旧鍵による移行承認と新鍵事前同梱で実施。漏えい時に自動更新へ依存しない緊急手動更新手段を用意。

## ログと性能ダッシュボード

- ログはClient/Hostの個別ユーザーディレクトリに保存。回転・容量上限・保存期間は初期例 7日 / 合計100MiB（設定可能）。
- 表示: renderFPS、captureFPS、encode/decode/render時間、RTT、frame age、欠落、bitrate、CPU/GPU、RAM、転送状況、接続状態。
- 画面内容、入力した文字、クリップボード本文、ファイル本文、ペアリング秘密鍵はログに残さない。IPや端末識別子のエクスポート時は匿名化を選べる。自動テレメトリ送信なし。

## 本番公開前の必須安全テスト

改ざん更新の拒否、旧バージョンへのロールバック、未認証Clientの拒否、2台同時接続、鍵変更/再接続、フォルダのパストラバーサル、ファイルのシンボリックリンク、IP復旧失敗、ネットワークHelperの権限逸脱、Hub/Hostユーザーセッション混同、High Sierraでの署名付き更新。
