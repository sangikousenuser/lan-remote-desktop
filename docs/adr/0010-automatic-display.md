# 0010: 実測負荷を使う初回解像度選択

対象: Q22/Q30/Q31。日付: 2026-10-19。

新規の承認済み接続で、最初の描画・復号が動いてから初回モードを選ぶ。Macの物理/論理画素、表示refresh、実測decode/render工程時間、実際のhardware decoder選択、Windowsが列挙した対応モードを使う。codec能力を機種名だけから推測しない。

- 選択関数は最大128モードと数値capabilityだけを受け取り、広告された有効モードの中から返す。NaN/無限/異常寸法を拒否する。
- 目標fpsはMac refreshから30〜60。工程の遅い方を用い、1frame予算の70%を初期のpixel budgetへ割り当てる。hardware時の上限は4K、software時は論理画素数と1080pの小さい方。物理画素を目安の上限にし、対応モードがない場合は近いモードと比率維持の描画を使う。
- aspect・解像度距離・pixel budget超過・refresh不足を評価する。非対応モードを生成しない。これは初期推定であり60fpsの保証ではない。
- shader等の最初の初期化を避け、2frame以上の描画完了・1秒以上経過後の最新工程windowを使用する。
- Windowsは既存の表示journal/leaseで変更前を保存してから適用する。入力を解放し、世代を更新し、新しい描画が完了するまで取得し直さない。
- 120秒内の復帰では再選択せず、維持しているWindowsモードを引き継ぐ。手動のモニター/モード選択は自動選択を取り消す。「Macに合わせてWindows解像度を自動調整」をOFFにして現在のWindows解像度を維持できる。

純粋関数の試験で高速hardware/遅いdecode/software/Retina/aspect/未対応・不正capabilityを確認する。表示ドライバーごとの適用・復元と最終描画性能は最後の実機受入で確認する。
